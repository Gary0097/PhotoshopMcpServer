# 端行项目最终验收差距矩阵

> 审计日期：2026-08-30  
> 审计基线：本文件所在提交  
> 用途：区分“软件已经具备的能力”和“必须由端行现场确认的工艺结果”，防止以自动测试替代客户验收。

## 一、审计结论

当前版本已经达到现场 POC 的软件前置条件，但尚未达到 PRD 所定义的首期最终验收条件。

- 本机连续 5 次完成 MCP 初始化、客户工具列表读取和中文帮助调用，5 次全部通过。
- 121 项自动化测试全部通过。
- Photoshop 27.4.0 与 Illustrator 30.1.0 已完成真实创建、保存和导出。
- 单张、中文规格模板、两张批量、预览、复核、审批绑定、TIFF 导出和原图保护已完成真实流程自检。
- 最终工艺效果、AI 数据政策、真实高 DPI 样板、部署耗时和 UAT 签字仍缺少甲方现场证据，因此不能写成“项目最终验收完成”。

## 三、现场必须提供的最小输入

以下六项缺一不可；缺失时实施人员应停止宣称“最终验收完成”：

1. 可正常使用的 VPN、已购买 GPT 服务、已安装并登录的 Codex。
2. 已授权的 Photoshop 2026、Illustrator 2026 和现场安装权限。
3. 至少 1 类代表性纹理及建议 3～5 张 POC 样板。
4. 成品尺寸、DPI、格式、色彩模式、位深、命名和最大文件规模。
5. AI 图片是否允许外发、使用哪个服务、谁承担账号费用及数据删除规则。
6. 设计/工艺/质检复核人，以及最终签字人。

## 四、现场完成顺序

1. 双击一键安装，记录开始和完成时间。
2. 连续运行环境、Adobe 与完整流程自检，保存版本和产物证据。
3. 工艺人员跟做代表性样板，形成首条正式模板并命名。
4. 使用 3～5 张样板做 POC，记录人工基线和自动流程耗时。
5. 冻结适用边界、参数和验收标准；问题区分为缺陷、工艺边界、数据问题或新增需求。
6. 使用 1～3 张验收样板做 UAT，甲方指定人员在中文交付报告中签字。

## 五、最终完成判定

只有本矩阵所有“部分证明”和“未完成”项取得现场证据后，项目目标才可标记为完成。在此之前，准确状态是：**软件已具备现场 POC 条件，等待端行环境、代表性样板、AI 政策与验收人员。**
